# rvben/homebrew-tap

CLI tools for infrastructure, automation, and daily workflows.

## Install

Install a tool directly from the shared tap:

```sh
brew install rvben/tap/unifi-cli
```

Or add the tap first, then use short formula names:

```sh
brew tap rvben/tap
brew install unifi-cli
```

Keep installed tools current with `brew update` and `brew upgrade`.
Homebrew may ask you to trust a third-party formula before installing it.

All ten new formulas support Apple Silicon and Intel Macs, and ARM64 and
x86-64 Linux. ServiceNow and Teams use native macOS binaries and source builds
on Linux, avoiding the published binaries' glibc 2.39 requirement.
OneNote, ru, and uvlazy build from source, with Homebrew supplying the build tools.
The ru source recipe guards a dependency patch that avoids a startup failure.
OneNote requires access to a Windows desktop running OneNote through an SSH
profile.
shinylive-check installs an isolated Python environment; follow its caveats to install
Chromium for your account before running browser checks.

## Maintenance

Upstream projects publish releases with `vership`. Existing projects keep their
upstream tap update jobs. The ten projects listed in `packaging/projects.json` are
managed here, without additional upstream deploy keys:

```sh
python3 scripts/update_formulas.py           # pin published releases
python3 scripts/update_formulas.py teams-cli # update one managed formula
python3 scripts/update_formulas.py --refresh # re-pin after template/config changes
python3 scripts/update_formulas.py --check   # offline check against committed pins
python3 -m unittest discover -s tests -v
python3 scripts/test_install.py              # real installs in a temporary tap
```

The updater downloads each required asset, verifies any GitHub release digest,
checks archive contents, and records SHA-256 hashes in `packaging/versions.json`.
Missing assets, checksum mismatches, or downgrades stop the update. Python runtime
resources are pinned in the template and maintained separately; `pip check` is part
of the formula test.

A daily workflow prepares a review branch and writes its comparison link in the
Actions summary. It explicitly dispatches native CI for that branch. A maintainer
integrates it after the checks pass, then deletes the review branch (especially
when squashing). While an unmerged review branch exists, later runs wait.

The workflow never pushes to the default branch, changes protection settings, or
requires permission for Actions to create or approve pull requests. CI checks the
generated formulas and tests native installs on both architectures on macOS
and Linux. Separate Debian 12 jobs check native Linux binaries on both
architectures, including checksums and runtime library dependencies.

Intel macOS builds Homebrew dependencies in separate foundation, LLVM, Rust,
and runtime jobs because new Intel bottles are no longer available. Each
completed stage is cached against its dependency recipes, Homebrew revision,
macOS version, SDK, and compiler. Homebrew and core revisions are pinned in
`packaging/intel-toolchain.json`; refresh these deliberately when updating the
build toolchain. Retries resume from the latest matching stage; the final job
still installs and tests every managed formula. A cold dependency build can take
several hours. Cancelling it preserves only stages that have already completed.
New pushes queue without cancelling a running build. Fork pull requests consume
matching default-branch caches and fail clearly if a maintainer needs to warm one.
A successful cold review run retains its runtime dependencies for one day, allowing
integration of that identical commit to seed the default-branch cache without
another cold build. The handoff accepts only successful runs of this workflow
from this repository, with the exact same commit and dependency keys. It requires
all stages to have been built in that run, with each restore checked against its
producer job's checksum. Resumed branch caches are never promoted this way.
If a runner compiler or SDK update invalidates the default-branch cache, run CI
manually with `workflow_dispatch` on the default branch to rebuild it.

The install test refuses to replace an existing managed installation. It uses a
temporary tap and trust configuration, installs without linking, and removes only
the test formulas. Homebrew dependencies are retained and autoremove is disabled.
